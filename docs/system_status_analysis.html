🔍 Architecture Insights

CQRS Pattern Implementation

The job service uses Command Query Responsibility Segregation:

  • Query Side: Read operations cached with Redis, optimized for performance

🔧 Root Cause Analysis & Fixes Applied

Issue #1: Database Health Probe Misconfiguration (CRITICAL)

Problem: Health probes were checking non-existent databases

  • userdb-postgres probe checked "userservice" database (doesn't exist)
  • jobdb-postgres probe checked "jobservice" database (doesn't exist)
  • Kubernetes killed pods when probes failed → 31 and 28 restarts

Fix: Added -d userdb and -d jobdb flags to probes

Files Modified:

  • k8s/backend/user/postgres.yaml
  • k8s/backend/job/postgres.yaml

Result: ✅ Databases now completely stable with 0 restarts since fix

Issue #2: Memory Overcommitment (CRITICAL)

Problem: Minikube limited to 3GB, but pods requested 9.8GB (118% overcommit)

  • WSL2 configured for 12GB but Docker container only had 3GB
  • Memory usage at 94.48% (2.8GB / 3GB)
  • Linux OOM killer terminating processes under pressure

Fix: Recreated minikube with 10GB allocation

Command: minikube start --memory=10240 --cpus=4

Result: ✅ Memory now at healthy 36% usage (3.6GB / 10GB), 64% headroom

Issue #3: Probe Timeout Too Short

Problem: 1-second timeout insufficient for PostgreSQL recovery

Fix: Increased timeouts to 10s, added resource limits, extended liveness delay to 60s

Result: ✅ Pods survive crash recovery without being killed
